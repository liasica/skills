# 合并全局记忆

把同目录 `global-memory.md` 的规则合并进用户自己的全局记忆。按语义逐条合并，不整文件覆盖。

## 1. 定位目标文件

| harness | 全局记忆 |
| --- | --- |
| Claude Code | `~/.claude/CLAUDE.md` |
| Codex | `${CODEX_HOME:-~/.codex}/AGENTS.override.md`，该文件不存在或为空时用同目录 `AGENTS.md` |
| Gemini CLI | `~/.gemini/GEMINI.md` |

- 默认目标是当前 harness 的文件，用户另行指定时以用户为准
- 用 `ls -la` 检查上表每个文件。软链写入 `realpath` 指向的真实文件，保留软链本身；多个路径指向同一真实文件时只合并一次
- 其他 harness 的文件内容独立时，询问是否一并合并
- 目标文件不存在时，经用户同意后新建
- Windows 上 `~` 指 `%USERPROFILE%`；没有 Bash 时用 PowerShell 的等价命令，写入时用不带 BOM 的 UTF-8

## 2. 逐条分类

读取目标文件与 `global-memory.md`，把来源按小节拆成单条规则，与目标的全部内容比对。每个列表项或段落算一条，一条里只有部分命中时按部分分别处理：

| 分类 | 判定 | 默认处理 |
| --- | --- | --- |
| 已有 | 目标已有含义相同的规则，措辞不同也算 | 跳过 |
| 新增 | 目标未涉及 | 写入 |
| 冲突 | 两条规则无法同时遵守，如对话语言、默认分支、测试要求、提交授权 | 保留目标原文，由用户裁决 |
| 需确认 | 来源「需逐条确认」小节的条目 | 不写入，由用户逐条决定 |

目标文件主体用中文以外的语言书写时，询问规则写入原文还是译成该语言。

## 3. 确认方案

向用户列出每条规则的分类、目标现状与拟定处理，并逐条询问冲突与需确认条目。用户确认前不修改任何文件；没有可写入的内容时直接汇报，不备份。

## 4. 写入

1. 目标文件已存在时先备份真实文件：

   ```bash
   target="$(realpath <目标文件>)"
   backup="$target.bak.$(date +%Y%m%d%H%M%S)"
   cp "$target" "$backup"
   ```

2. 规则追加到目标中主题相同的小节末尾，没有相应小节时按来源的小节标题与顺序新建，放在文件末尾
3. 来源开头不属于任何小节的内容放在目标文件开头，一级标题之后
4. 小节开头的说明句只在整个小节新建时写入，并入已有小节时不写入
5. 用户同意的需确认条目并入对应主题的小节，不写入「需逐条确认」这个标题
6. 除用户裁决采用来源的冲突条目外，不改动、不重排、不删除目标原有内容
7. 不写入「合并自」「来源」「合并时间」之类的标记

## 5. 汇报

报告写入文件的真实路径、四类规则各自的条数、冲突的裁决结果、备份路径，并给出回滚命令：

```bash
cp "$backup" "$target"
```
